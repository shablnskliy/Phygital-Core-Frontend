# Итерация 14 — аудит и обращения

Дата проверки: 8 октября 2026. Требования 175–192; предыдущий дизайн сохранён.

## Что исправлено

- Контакты и FAQ используют один FeedbackForm и feedbackService. Имя, email, одна из шести заданных тем и сообщение валидируются; дата, id и статус new создаются сервисом.
- Сохранение идёт в общий документ admin-state-v4 в IndexedDB, не напрямую из формы. Успех показывается только после завершения транзакции. При ошибке введённые данные остаются.
- Добавлен защищённый маршрут /admin/feedback: таблица, превью, полный текст, mailto, поиск, статусы, сброс, пагинация и badge новых непросмотренных сообщений. Первое открытие сохраняет viewedAt; смена статуса пишет административный лог.
- Общий storage использует атомарный read-modify-write и уведомления в текущей и других вкладках. Обращения не перезаписывают команды, пользователей или логи.
- Действия store ожидают сохранения. Добавлены проверки повторного ответа/приглашения непосредственно внутри транзакции; изменения названия и дат валидируются. Удаление турнира очищает связанные заявки.
- Исправлены production-переходы Vinext beta.5/Vite 8: совместимый transform в vite.config.ts сохраняет namespace router imports. App Router и постоянный Header сохранены; node_modules не изменялись.
- Кнопка подробностей турнира открывает рабочее окно вместо заглушки. Ближайший турнир на главной и в профиле берётся из общего store. Изображение турнира сохраняется, а не хранится как временный object URL.
- Исправлены собственный диапазон статистики и пересчёт графика; используются реальные временные поля, включая обращения. Пустой период показывает нули.

## Проверки

Автоматические проверки реального TypeScript-кода: npm run test:feedback — 75 assertions.

- 33: валидация, нормализация, права, поиск по id, просмотр, статусы/логи, отсутствие лишних логов, сохранение соседних коллекций, конкурентная отправка, abort и ошибка открытия хранилища.
- 42: пользовательское и административное создание команды, слоты/дубли, приглашения, чужие права, принятие/отклонение/отмена, один капитан, удаление участника, переименование, заявки, валидация турнира, удаление связанных данных и журнал.
- В тестах используется минимальная модель IndexedDB и React hook host для инъекции ошибок; это не заменяет браузерную проверку. Пользовательские данные браузера тесты не меняют.

Браузерные сценарии на локальной production-сборке:

- регистрация тестового пользователя, вход/выход, восстановление после reload, сохранение телефона в профиле;
- создание команды капитаном, поиск по имени/фамилии/полному имени/частичному телефону, маскирование номера и блокировка повторного приглашения;
- badge уведомлений, принятие и отклонение, уведомления капитана, обновление публичного состава и таблицы приглашений администратора;
- административное создание команды из двух найденных пользователей через свободные слоты с выбором капитана;
- подробности турнира, заявка с выбором капитанской команды без поля капитана, сохранение и одобрение в админке;
- обязательные поля обратной связи, точный success-текст, повторная отправка;
- live-появление обращения в другой вкладке без reload, badge, просмотр, сохранение статусов «В работе / Закрыто» после reload;
- поиск/пустая выдача, фильтр, сброс и переход на вторую страницу из девяти обращений; наличие смен статуса в логах;
- все периоды статистики: сегодня, 7/30 дней, месяц, год; свой период 01–02.01.2020 — все показатели 0 и корректный empty state.

Смена пароля, сброс пароля, смена роли и удаление пользователей проверены на уровне прав и кода, но не выполнялись через UI над пользовательскими аккаунтами. Полный серверный, почтовый и многопользовательский E2E отсутствует, поскольку backend пока нет.

Финальная проверка production: все 17 страниц открыты через рабочую навигацию; в новой проверочной вкладке console error/warn — 0. Проверены mobile 390×844 и tablet 820×1180: contacts и обращения не расширяют документ за viewport; широкая таблица прокручивается внутри контейнера. Мобильные меню и окно обращения открываются и закрываются. Скриншоты сохранены отдельно в outputs/v14-verification.

Итоговые команды npx tsc --noEmit, npm run lint, npm run test:feedback и npm run build проходят. Информационные предупреждения сборщика о производительности плагинов/классификации маршрутов не являются runtime-ошибками. Node предупреждает об experimental-vm-modules только при запуске тестового harness.

## Ограничения демо

Все данные локальные: другой браузер, hostname или порт — отдельное хранилище. BroadcastChannel синхронизирует вкладки одного origin, а не разные компьютеры. Проверки ролей на frontend не являются серверной защитой. Перед публикацией нужны backend, серверная авторизация и обработка обращений/почты. В архив не входят тестовые аккаунты и сообщения браузера, node_modules, runtime-кэши и секреты.
