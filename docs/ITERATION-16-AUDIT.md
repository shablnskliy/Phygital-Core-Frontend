# v16 — композиция модальных окон, правки 215–234

## Изменения

- Общий Modal разделён на header, прокручиваемый content и опциональный отдельный footer. Новый CloseButton используется всеми окнами на основе Modal: SVG X, область 40×40, одинаковые отступы сверху и справа, ghost-hover, disabled при сохранении.
- «Подробнее о турнире»: статус над названием, краткое описание, компактная сетка даты/времени/места/подтверждённых команд, отдельный блок «О турнире» и ссылка на правила. Вместимость не выдумывается, отсутствующие данные не подменяются фиктивными.
- «Заявка на турнир»: название текущего турнира, команда из существующего капитанского состава, необязательный текст до 500 символов, счётчик и сообщение об ошибке. Поля выбора/подтверждения капитана нет.
- Новый SelectField: тёмный раскрывающийся список, selected/hover/focus/disabled, aria-combobox/listbox/option, стрелки, Home/End, Enter/Space, Escape, Tab и закрытие при клике вне списка. Escape сначала закрывает список, а не всё окно.
- При отсутствии капитанских команд показан отдельный empty state с текстами из ТЗ и работающей кнопкой «Создать команду». После создания команда возвращается в заявку. Гостю предложена авторизация.
- Оба footer используют ModalFooter: вторичное действие и основная CTA справа, согласованные высота/радиус/типографика. Submit-кнопка связана с формой нативным атрибутом form. Добавлена синхронная защита от повторной отправки; существующие проверки прав и сохранение в локальном сервисе не менялись.
- Ширина подробностей 720 px, заявки 580 px; внутренний padding 32 px desktop и 22 px mobile. На телефоне кнопки footer идут колонкой. Footer вне прокручиваемого контента; header с крестиком остаётся доступен.
- Затемнённый overlay с blur, тёмная поверхность, тонкая violet-граница, мягкая тень/glow, открытие 220 ms. Для prefers-reduced-motion анимация отключена.
- Удалены старые стили отдельных турнирных окон из interactions.css; новый каркас и композиция описаны в modals.css. Для остальных существующих form-actions внутри Modal унифицированы выравнивание, разделитель и размеры кнопок; их обработчики не менялись.
- Header сайта, Hero, Footer сайта, изображения, тексты страниц и сервисная бизнес-логика не перерабатывались. Sites применён только для локального рабочего процесса, без публикации.

## Пройденные проверки

- `npx tsc --noEmit` — успешно.
- `npm run lint` — успешно.
- `npm run test:feedback` — 134 автоматических утверждения: 33 обратной связи, 58 платформенных действий, 12 Button и 31 Modal/SelectField.
- Новые проверки исполняют TSX-компоненты в VM с тестовым React-окружением: структура трёх зон, CloseButton, aria-связи, dropdown, клавиатурные обработчики и disabled. Это не E2E-тест реального браузера.
- Предыдущие проверки локальных сервисов, прав капитана, заявок, команд, приглашений, сохранения и журналирования продолжают проходить.

## Ограничения проверки этой версии

`npm run build` не завершён: загрузка vite.config.ts остановилась на `EPERM: operation not permitted, realpath` в node_modules (react, react-dom, vite). Диагностический вызов Node показал, что обычный fs.realpathSync доступен, а fs.realpathSync.native для тех же файлов получает EPERM. Разрешения на чтение зависимостей и служебные кэши запрашивались, но ограничение сохранилось. Зависимости и рабочая конфигурация сборки не переписывались для обхода ограничений среды.

Production-сборка, HTTP smoke и интерактивная/визуальная проверка v16, в том числе mobile и реальная работа focus/hover, не подтверждены. Результаты и скриншоты предыдущих версий не являются доказательством проверки v16. Для завершения проверки на обычном локальном окружении выполнить команды из README и проверить оба окна под гостем, капитаном и обычным участником, включая длинное название, несколько команд, пустой состав, ошибки и повторную отправку.

Архив содержит исходники и локальные assets, но не node_modules и не старую сборку dist. Backend по-прежнему отсутствует: данные и права работают только в локальном mock-режиме одного браузера/origin.
