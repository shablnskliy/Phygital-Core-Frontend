# Phygital Core

Текущая версия исходников: v17. Удалена механика заявок на создание команды, выполнен FSD-рефакторинг по правкам 235–268. Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Проверки и ограничения: [docs/ITERATION-17-AUDIT.md](docs/ITERATION-17-AUDIT.md). Предыдущие правки модальных окон турниров сохранены: [docs/ITERATION-16-AUDIT.md](docs/ITERATION-16-AUDIT.md).

Полностью адаптивный frontend платформы фиджитал-турниров. Проект работает без backend: аккаунты, сессия, профиль и административные изменения сохраняются локально в браузере. Стек сохранён — React 19, TypeScript 5.9, Next.js App Router API через Vinext, Vite 8 и Cloudflare Workers.

## Запуск

Требуются Node.js 22.13+ и npm 10+.

```bash
npm install
npm run dev
```

Сайт откроется на `http://localhost:5173`.

Проверки и production-сборка:

```bash
npm run lint
npm run format:check
npm run typecheck
npm run check:architecture
npm run test:feedback
npm run build
npm run start
```

## Маршруты и права

Публичные страницы: `/`, `/tournaments`, `/teams`, `/rules`, `/faq`, `/contacts`, `/privacy`. Отдельные маршруты турниров, входа и регистрации удалены; авторизация работает в едином модальном окне поверх текущей страницы.

`/profile` требует авторизации. Для гостя открывается модальное окно входа с возвратом в запрошенный раздел после успешной авторизации.

Административные страницы `/admin`, `/admin/users`, `/admin/teams`, `/admin/tournaments`, `/admin/tournament-applications`, `/admin/invitations`, `/admin/feedback`, `/admin/logs` требуют роли `ADMIN`. Авторизованный пользователь без этой роли видит страницу 403. Раздела заявок на создание команды больше нет.

## Архитектура

Код следует Feature-Sliced Design и направлению зависимостей `app → pages → widgets → features → entities → shared`:

- `src/app` — providers, глобальные стили и сборка layouts;
- `src/pages` — отдельные slices экранов, композиция widgets и features;
- `src/widgets` — header/footer, PageHeader, списки, ЛК и административные блоки;
- `src/features` — вход, создание/управление командой, приглашения, формы и фильтры;
- `src/entities` — единые типы, данные, авторизация и платформенные операции;
- `src/shared` — UI, API-контракты, конфигурация, централизованное storage и утилиты.

Next.js App Router сохранён в корневом `app/`: это тонкие адаптеры к FSD-экранам. Корневой `pages/` содержит только README, не маршруты; он предотвращает интерпретацию `src/pages` как Next.js Pages Router. Каждый slice имеет `index.ts`; внутри slice используются относительные импорты, снаружи — его публичный API через `@/`. Разрешённые связи бизнес-сущностей явно оформлены через `@x/platform` и `@x/feedback`. Проверка архитектуры запрещает импорты вверх, соседние features/widgets, обход public API и runtime-циклы.

Поток данных авторизации: `UI → AuthProvider → authService → localDataSource → storageService`. Общие платформенные данные проходят через `PlatformProvider → domain actions → platformService → IndexedDB`; обращения — через `feedbackService` в тот же документ. Изменения сохраняются атомарно, обновляют интерфейс и синхронизируются между вкладками одного origin через BroadcastChannel. Прямых вызовов localStorage в компонентах нет. Для REST API заменяются сервисы/data source; серверные права и настоящая общая база обязательны перед production-запуском.

## Реализованные сценарии

- реальный локальный вход, регистрация, выход, восстановление сессии и две роли;
- редактируемый профиль с сохранением после перезагрузки и сменой пароля;
- защищённые маршруты, страницы 403/404 и error boundary;
- заявка на турнир с выбором существующей команды, автоматическим определением капитана и необязательным комментарием до 500 символов;
- FAQ с заданным набором тем и рабочей формой вопроса;
- единая форма обратной связи в контактах и FAQ: валидация, надёжное сохранение, очистка только после успешной транзакции;
- раздел «Обращения» с badge, поиском, фильтрами, пагинацией, просмотром полного сообщения и статусами «Новое / В работе / Закрыто»;
- приглашения в команду с уведомлениями, принятием/отклонением и обновлением состава во всех связанных экранах;
- создание команды администратором через динамический список игроков, поиск зарегистрированных пользователей, удаление игрока и выбор одного капитана из состава;
- состояния поиска игроков: загрузка, результаты, ничего не найдено, ошибка и повтор;
- создание турнира только с разрешёнными полями; статус рассчитывается автоматически по датам;
- рабочие поиск, фильтры, сброс, вкладки, пагинация, просмотр, создание, редактирование, решения по заявкам, роли, сброс пароля, подтверждение удаления и административный лог;
- loading/disabled, валидация и сообщения об успехе/ошибке для мутаций;
- единая тёмная неоновая тема, responsive UI для desktop/tablet/mobile и reduced-motion режим;
- непрерывная анимированная лента ценностей и scroll-reveal анимации на публичных страницах;
- viewport-safe модальные окна через portal: фон блокируется, содержимое прокручивается независимо и не конфликтует с футером.

## Графика

Локальные декоративные изображения находятся в `public/` и имеют оптимизированные WebP-версии:

- `hero.webp` — главный экран;
- `trophy-arena.webp` и `team-arena.webp` — используемые блоки главной;
- `page-objects/*.png` и `page-objects/*.webp` — единая серия прозрачных декоративных объектов внутренних страниц;
- `brand-logo.png` — предоставленный оригинал; `brand-logo-header.webp`, `brand-logo-footer.webp`, `favicon.png` — оптимизированные версии знака.

Изображения не содержат встроенного текста, интерфейсных элементов, чужих логотипов или товарных знаков. PNG-исходники оставлены рядом для дальнейшей обработки.

## Локальные данные

Демо-версия не передаёт введённые данные на сервер и не отправляет письма: текст подтверждения означает получение обращения локальным сервисом. Данные доступны только в этом браузере и на том же origin (протокол, hostname, порт). Это не многопользовательский backend; настоящую авторизацию, права, отправку почты и общую базу нужно реализовать на сервере перед публичным запуском. Очистка данных сайта сбрасывает аккаунты и административные изменения.
